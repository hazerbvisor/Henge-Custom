# Lower RAM slow-read overhead

`hv_vmem_xfer` first resolves a physical address and validates its complete RAM range with `hv_phys_ptr`. It previously called `hv_phys_read`, which resolved and validated the same range a second time before copying. Reuse the returned pointer for the RAM read copy. Writes still call `hv_phys_write`, retaining ROM behavior, write watches and code-page invalidation. MMU permission checks, fault handling, 4 KiB splitting and the MMIO path are preserved. No cache, allocation, lock, counter or per-CPU metadata is added. The translator and generated ALU code are unchanged from the preceding release.

Two local paired benchmark invocations, software MMU enabled, each discard one warm-up round and alternate short baseline/candidate batches in the same process. RAM slow-read time fell approximately 22–25% for 8/64-byte and cross-page cases, and 8.1–8.3% for the 4096-byte case. All 18 read pairs per scenario improved. Write controls were effectively unchanged (0.02% / 0.42% paired median improvement). A separate diagnostics-enabled pass improved small reads by 18–21% and the 4096-byte case by 8.4%. See the summary JSON and raw release attachments. These are isolated helper timings; they do not imply equivalent Roblox FPS gains.

Validation: 1536 original/candidate transfers compare returned data, resulting RAM, exception state and ordered device accesses across MMU on/off, EL0/EL1, diagnostics on/off, read/write, ROM, unmapped addresses, partial MMIO operations and page edges. Full native engine/device regressions pass (135 device checks), including the scratch-selection tests from the preceding release. Test fixtures never open existing guest disks. A separate experiment to reduce translation bookkeeping introduced regressions with diagnostics off and was excluded. Reverting the earlier operand-scanning change produced no clear ALU gain and was excluded too.

Reproduce: `python3 tools/benchmark_vmem.py` and `HV_BENCH_STATS=1 python3 tools/benchmark_vmem.py`. For equivalence only: `make test-vmem-equivalence`. Baseline is pinned to eaf01e9; a Git checkout containing that revision is required. Native engine checks: `make B=build/check CC='clang -Wl,-stack_size,0x4000000' test-engine` with `HV_TEST_WORK` set to a unique temporary directory. The stack linker flag is test-only.

Physical iPad boot and game frame-time improvement remain unverified. Publish as a prerelease for device comparison. Existing VM settings and the optional mouse-button swap are preserved.
